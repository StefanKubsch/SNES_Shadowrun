# Render routines

Reference for the original render, transfer, palette, input, audio, text and
menu routines and their manual native plans (mostly in `proof/render/`). It
condenses the former `RENDER-*` contract files (source contracts and their
`-NATIV` counterparts are merged per routine); shared terms are in
[the reference index](README.md#shared-contract-terms). Current work:
[PROJECT-STATUS.json](../PROJECT-STATUS.json).

Common rules for the native render plans: the manual render byte provider
(`createRenderData`) holds only explicitly supplied bytes and write windows;
`prepareRenderXXXX()` returns an immutable plan bound to its owner and data
revision, applied only by `data.commit(plan)`; inner `renderXXXX(view,
context, budget)` functions share the view and budget of an outer owner and
have no commit payload of their own; any missing source, write window, I/O
context, stack separation or budget gives `handled:false` with `reason` and
`phase` and no partial writes or requests; foreign, copied, stale or reused
plans are rejected. System bank register stores are recorded only as
ordered request metadata (`ioMode: 'record-requests'`); in banks 7E/7F the
same offsets are real WRAM bytes. Hardware results (products, quotients,
APU tokens, counters, joypad words) are explicit chronological observations,
never computed; a counter change proves no time, frame, interrupt or
transfer completion. `maxWork`/`maxOutputBytes` are host limits, not CPU
time. Probes in `analysis/render-*-native.json` use explicitly synthetic
fixtures and prove no original scene. Not covered anywhere here: automatic
NMI/frame binding, original initialisation, E382 boot/SPC, native A5/97.
