# Task interpreter opcode handlers

Reference for the original script interpreter dispatch at `80:F390` and
every proven opcode handler. It condenses the former per-handler contract
files; the shared terms are in [the reference index](README.md#shared-contract-terms).
Current work is tracked only in
[PROJECT-STATUS.json](../PROJECT-STATUS.json); historical continuation state is in
[PORTIERUNGSSTAND.json](../PORTIERUNGSSTAND.json).

## Dispatch at 80:F390

Original `80:F390`, bytes `7C B4 F2`, is `JMP ($F2B4,X)` in E0/M0/X0. The
full observed WORD X selects the bank 80 address `(F2B4+X)&FFFF`; the high
byte also wraps within bank 80. Neither D nor DBR selects the table. The
source has no ASL, opcode clamp or parity guard. The JMP only changes PC,
creates no return frame and writes no data.

- [Source report](../../analysis/render-task-opcode-dispatch.json) pins the
  original window. The [native target reader](../../proof/task/opcode-target.mjs)
  reads both real provider bytes in source order; its separately prepared
  plan reports the target and does not execute it. Odd and high X values read
  their real addresses.
- The [opcode composition](../../proof/task/opcode-sequence.mjs) admits only
  individually proven index/target pairs. Each slot has its own contract
  with the original table bytes, complete handler windows and the re-checked
  existing source proof. No ROM instructions are decoded or executed.
- `prepareTaskOpcodeSequence(options)` requires `entry=0x80F390`, a frozen
  E0/M0/X0 context, explicit physical byte sources, protected outer return
  owners, write windows, `maxWork`, `maxOutputBytes` and a positive safe
  integer `maxHandlers`. The per-slot exports (`prepareTaskOpcodeXX`)
  additionally require exactly their first X index. Every handler processes
  its operands and ends at its freshly read F390 or at a separately proven
  terminal prefix limit. Later handlers see earlier writes; the table is
  reread on every dispatch. After exactly `maxHandlers` the plan stops before
  the next F390 target read; termination is never guessed from results,
  opcodes or game time.
- One overlay collects all reads, writes and cumulative costs; only
  `commitTaskPlan(data,plan)` applies the plan. Missing table/operand/pointer/
  opcode high bytes, changed table targets, unproven slots, decimal
  add/subtract paths, protected stack aliases, unwritable bytes, late budget
  failures and stale or foreign plans discard all earlier effects.
- BEQ/BNE test the full WORD condition. Jumps not taken read no target
  operand; taken jumps read the full target and set WORD Y without host PC
  normalisation. Backward jumps consume the same handler count even without
  writes or Y progress. State accesses keep full WORD indices; at index FFFF
  the state high byte comes from 7F:0000. BYTE stores write only the low
  byte; WORD stores can replace the own DP pointer. Program bank 80 table
  bytes are independent of WRAM state offsets with the same number.
- Local writes 2C/34 keep the WORD index and WORD PLA before the store.
  4C/50 use the real DP05 pointer and return bytes in actualDBR; a return
  store may replace DP05 and the following reload is fresh. S stays
  unchanged; there is no host call stack.
- Arithmetic 60–6E and 70–76 compose the manually proven equations; the
  older source reports keep `source_closed_to_dispatch=false` for their open
  dynamic follow-up dispatch. Multiplication and division need one frozen
  ordered `ioObservations` list across the whole sequence
  (`{pc,address,width,value}`, `ioMode=record-requests` for unmapped MMIO);
  missing, wrong or surplus observations discard writes and requests. In WRAM
  and ROM the same absolute addresses stay normal provider accesses.
  Remainder paths work on the original saved Y and are bounded only by the
  access budget, without a modulo replacement or ROM loop cap.
- The prefix API lets 52 end before F488 TCS and 58 before F4F6 TCS; both
  store the original argument/PC/ID/operand-S prefix with fresh own alias
  reads. The [full Native58 API](task-natives.md#native-opcode) composes 58
  through the bridge, fresh A2, 59 individually proven leaf/RTS targets and
  resume to F390. The [Script52 API](task-scripts.md#script-opcode) binds 52
  up to the real outer yield via original heap/frame creation and child
  insertion; this yield is terminal. 56 restores the fresh outer S, requires
  the real protected return bytes and only reports the original RTS target.
- Original slots 54/90/98/A0/A8 are `JMP F927`, not assumed yield or compare
  handlers; their prefix API stops before F927 ([trap-prefix source](../../analysis/render-task-trap-prefix.json)). The 24 remaining even slots
  up to C2 lead directly to F927 ([status-return](#status-return)). All 98
  even original slots 00..C2 are individually proven; odd and high indices
  remain real table reads that need their own contracts.
- A terminal prefix limit is only allowed at the end of the requested
  handler count. Any further requested step reports
  `task_opcode_continuation_source_required` and rejects the whole sequence,
  including earlier writes.

Every slot below has its single contract and native probes, and its handler proof embeds the original handler windows, mode, stack, flag
and alias effects unchanged. All fixtures are synthetic; general
task/return/yield/migration, initialisation and scene/frame binding stay open.
