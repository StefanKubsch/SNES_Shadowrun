# Task natives (opcode 58 `call_native`)

Reference for the native routines that script opcode 58 calls through the
original Native58 path, and for the larger native graphs proven on their
own. It condenses the former `RENDER-TASK-NATIVE-*` contract files; shared
terms are in [the reference index](README.md#shared-contract-terms). Current
work: [PROJECT-STATUS.json](../PROJECT-STATUS.json); historical state:
[PORTIERUNGSSTAND.json](../PORTIERUNGSSTAND.json) (its Native58 table links each
proven target).

## Native58 call chain

<a id="native-opcode"></a>`prepareTaskNativeOpcodeSequence(options)` in
[opcode-sequence.mjs](../../proof/task/opcode-sequence.mjs) composes an
explicitly bounded original opcode sequence including the complete Native58;
`prepareTaskNativeOpcode58(options)` additionally requires the first X=58. The
per-target exports in [native-opcode-bindings.mjs](../../proof/task/native-opcode-bindings.mjs)
require exactly their freshly read callee target; the original argument ID
and table pointer are never cached targets. The older
`prepareTaskOpcodeSequence`/`prepareTaskOpcode58` prefix API still ends
before F4F6. Entry is F390 in a frozen E0/M0/X0/PBR80 context with a real
versioned byte provider, physical protected outer return owners, write
windows, `maxWork`, `maxOutputBytes` and a positive finite `maxHandlers`.
Native58 consumes exactly one handler, including callee and resume. All parts
use [native-opcode.mjs](../../proof/task/native-opcode.mjs) on one overlay,
one access/output/observation ledger and one outer commit.

Argument workspace may replace the saved ID or outer S; own stack writes may
change A2, result, PC or pointer, and the next source is always the real
memory value. Protected outer return bytes are never read or written as
data; the migrated outer frame must be physically proven before the bridge
and after the leaf RTS. There is no claimed global stack requirement.
Behaviour tests compare the full sequence with the separate prefix, bridge,
leaf and resume plans and cover repeated calls, 255 arguments, carry/ID wrap
and own PC/pointer aliases. The separate [Script52 composition](task-scripts.md#script-opcode)
binds arguments, heap/frame and child insertion up to the outer yield.

## Native task/render adapter

<a id="native-render"></a>Task-side adapters for the original render, text,
menu, audio and input helpers. They are separate from the render bindings in
[render-routines.md](render-routines.md) and do not replace a task adapter with
real inner stack stores. Common rules: every inner JSR/JSL/RTS/RTL,
PHA/PLA, PHX/PLX, PHY/PLY, PHP/PLP, PHB/PLB and PEI frame is really written
to bank 00 and read back fresh, and the return bytes must match before each
fixed continuation; every MMIO read and every wait or counter poll consumes
its own frozen chronological record (original PC, address, width, value), and
missing, swapped or unused records reject the plan; a counter change creates
no input and proves no time, VBlank, callback or transfer completion;
hardware products and quotients are never computed; one provider, one
cumulative budget and one outer commit per plan; reset value 3030 at a fresh
01CA read is a native reset/startup limit that publishes no effects. Helpers
and polls never count as script bodies.
