# Mesen2 oracle (M2)

Part of [STRATEGY.md](STRATEGY.md), milestone M2. Mesen2 runs only in tools
and tests, never in `src/`, and is not distributed with the repository
(GPL-3.0). Translated and condensed from the former German `MESEN-ORAKEL.md`
(original wording at git commit 20c7b6c9).

Fixed settings by command line, independent of Mesen's `settings.json`:
`--snes.ramPowerOnState=AllZeros` (otherwise random RAM power-on state),
`--snes.enableRandomPowerOnState=false`, `--snes.region=Auto`. Input: A and
Start pressed for 6 frames every 120 frames; optionally from `walkFrom` the
d-pad (right, down, pause, left, up, pause, `walkStep` frames each) or from
`planFrom` a command sequence (`hold`, `press`, `wait`, `glove` = glove in a
control loop onto a picture pixel). A run is reproducible; from about frame
1000 the script interpreter runs, around frame 2400 the character stands in the
morgue.

## Comparison

The state at `$F390` is the state the VM holds between two opcodes (X = A =
opcode). For every interval between two sync points the VM starts from the
first state (WRAM from start image plus all earlier writes) and must hit the
second: PC (`$F390` or return site), registers `a x y s d dbr p` and every WRAM
byte written by either side; all other bytes are equal through the shared start.

- From S the VM runs exactly one opcode with admitted natives via `run(1)`.
  If the opcode ends with an exit (task end, status return, script call, native
  wait `$C401`), `TaskScheduler` continues with budget 0 to the next `$F390` or
  the round return.
- From C the VM pushes the JSR return word and starts the round (`$96C0` →
  `$C1E3`, `$91D4`/`$E545`/`$E78E` → `$C1CA`) up to the first opcode or round
  end.
- From R at `$96C3` the VM runs the native main loop up to the next C at
  `$96C0`. Only fully run intervals with fully consumed observations count as
  `equal-main-loop`; in window `arch` five intervals are identical. Normal loop
  calls are bound ([VM-INTERPRETER.md](VM-INTERPRETER.md)); scene build and
  loop exits stay explicit breakpoints; other R→C intervals are taken over.
- If a native itself calls a round (dialog: `JSR $C1CA` at `$91D4`), the
  recording splits it at C and R. The VM still runs the native in one piece
  (since 2026-10-14): at the round it compares with C (without the two already
  pushed bytes of the JSR frame that Mesen does not yet have before the JSR);
  the round's intervals run from their recorded states; from R the native
  continues with the register and memory state of R and the observations of the
  interval after R, and its end is compared with the next point. Counters
  `equal-native-round-start`, `equal-native-round-end`. After such a round an
  interval is no longer repeated (added wait zeros); if the recording ends in
  the rest of the native the comparison reports
  `oracle_native_open_after_round`.
- The SRAM content at the first sync point is recorded; SRAM writes in the
  window carry `S` before the offset in the same write sequence and are compared
  like WRAM bytes (since 2026-10-15, saving in the bed menu `$CE6D`).
  Oracle-checked natives ([oracle-natives.mjs](../proof/vm/oracle-natives.mjs))
  run in the comparison.
- Special natives get the hardware reads of their interval as `ObservedDevices`
  set. Mesen reports the PC after the operands; the instruction address is
  determined from the operand in ROM (absolute or long). Arithmetic unit reads
  are computed by `VmMemory`.

NMI intervals (since 2026-10-14): the recorder marks writes between NMI start
and `RTI` (`$C14E`) with `!`, plus the interrupt frame (PB, PC, P) the CPU
pushed before on the running stack. The VM takes bytes whose last change in the
interval comes from the NMI as outer values and compares all others. Hardware
reads count only outside the NMI; two byte reads of the same instruction at
consecutive addresses are one 16-bit read (e.g. `$2134`). Wait loops (`LDA
$01Fx` / `BNE` to itself) are left only with value 0 and the number of passes
does not change the end state, so the comparison supplies one observation 0 per
loop entry; the module reports which loop follows (PC, address) and the attempt
is repeated from the same state. Recording the reads doubled the runtime and was
dropped.

Not compared but counted: writes outside the WRAM image and natives without
implementation. Faults with details are in `faults`. Self-check: the
reconstruction at the end equals Mesen's WRAM image.

Recorder section `q` (added for the punk dialog): observations in execution
order, only outside the NMI: `b` counter value `$7E1C76` last read by
`$81:B0A1` (at RTL; the counter is remembered by a read callback because
`emu.getState()` is too expensive in loops), `z` exit value of every wait loop
on a WRAM word (`LDA abs` with `BNE`/`BPL` to itself, list `WAIT_LOOPS` from the
ROM), `n` words written by the NMI that the code reads after the wait (`DP82`
after `$AE0C`/`$AE5E` and after the frame wait of the tile loop at `$AE23`; the
NMI processes the job list at `$81A958` and sets `DP82`; after the wait for
`$01FC` at `$81:ACC9` the eight words `$7E2AE0`–`$7E2AEE` that the NMI reads
from VRAM by DMA for glyph output `$FB39`; offsets from `$2000` are read as bank
`$7E`), `j` joypad word `$01CA` at entry to `$9E1A`. The comparison gives these
observations to the one special native of the interval; missing zeros for wait
loops are added only at the list end. `R` is now emitted only at the stack
pointer of the matching `C` (`$91D7` is also the normal RTS of `$9178`, text
without topic action; before, the dialog fell into two intervals there); stack
pointers are remembered also before recording start, otherwise the `R` of a
round starting before the first `S` is missing.

move it with the d-pad over an object until the tag box appears; B again opens
the action window (Exit/Examine/Open/Pickup), B confirms. R opens the door under
the glove directly, L examines directly. A is the crosshair, X the spell glove,
Y the inventory, Start the status screen, Select the party display. The glove is
in `$01D4`/`$01D6` (high byte = picture pixel). Object under the glove:
`$01DA` ≥ 0 and number in `$01DE` (shown only once the glove stands still), so
rooms can be mapped by raster scan. From afar the game says "Too far away."

The d-pad works isometrically: up-left increases x, down-right decreases x,
up-right increases y, down-left decreases y. After R on a door the glove is off;
another B switches it on. In plans found coordinates appear as `glove`.

## Coverage of the oracle windows

`npm run mesen:coverage` ([mesen-coverage.mjs](../tools/mesen-coverage.mjs))
records all windows of `ORACLE_WINDOWS` in parallel (about 3 minutes), compares
them and writes [analysis/mesen-coverage.json](../analysis/mesen-coverage.json).
Only what ran in an equal interval counts: the script base (word at D in the
task frame, bank DBR, equal to script address + 2), every native target of
opcode `$58` (including scheduler-served ones like `$C401`) and the opcodes;
paths inside a native are not measured.
